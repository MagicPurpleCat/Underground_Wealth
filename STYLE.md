# STYLE — правила стиля кода и текста

> Перезаписывается при обновлении конвенций.
> Все участники проекта соблюдают эти правила.

## Язык и формат
- Основной язык кода: TypeScript (ESM)
- Язык комментариев и документации: русский (продукт), английский допустим в коде идентификаторов

## Именование
- **Переменные:** camelCase
- **Константы:** UPPER_SNAKE_CASE
- **Классы / типы / компоненты:** PascalCase
- **Файлы:** kebab-case или camelCase по существующему соседству; React-компоненты — PascalCase
- **Компоненты:** PascalCase в `apps/web/src`

## Форматирование
- Отступ: 2 пробела (вкладки запрещены)
- Максимальная длина строки: ~100–120 (мягко)
- Точки с запятой: да
- Кавычки: одинарные в TS/TSX

## Импорты
- Порядок: сторонние → `@pb/*` / `@/` → относительные → стили
- Запрещены: `import *` без необходимости
- Группировка через пустые строки

## Комментарии
- Комментарии только для «почему», не для «что»
- JSDoc для публичных API при необходимости
- TODO с именем и датой: `// TODO(имя, YYYY-MM-DD): ...`

## Git / коммиты
- Формат сообщения: `type(scope): description`
- Типы: feat, fix, docs, refactor, test, chore, style
- Одна логическая задача — один коммит
- Запрещён коммит без сообщения
- Не коммитить `.env`, токены, `.bot.lock`

## Тесты
- Покрытие публичных функций (по мере появления)
- Имена тестов: `should_..._when_...`
- Arrange-Act-Assert структура

## UI
- shadcn + Tailwind; не смешивать с Astryx
- Стиль: amber/gold + copper, Roboto Slab + Source Sans 3
- Избегать purple/cream AI-клише

## Запрещено
- Отключение линтеров без причины в коммите
- Закомментированный код в production
- Секреты в репозитории / в чатах без необходимости
- Несколько процессов `pnpm bot` одновременно
